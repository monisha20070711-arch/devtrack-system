1. Project Idea & Business Case

Implemented in Project

DevTrack System is a full-stack SaaS Issue & Task Management System built using Node.js, Express.js, MySQL, and Vanilla Web technologies (HTML5, CSS3, ES6+ JavaScript). The name combines Developer and Tracking, symbolizing continuous oversight of software defects, feature enhancements, and system maintenance tasks across their entire lifecycle.

Real-World Problem Addressed

In modern software engineering, managing bug reports via unorganized channels (email threads, instant messaging, or flat spreadsheets) results in unassigned tasks, lost defect histories, and zero visibility into team capacity. DevTrack solves this by providing a single centralized dashboard where issues are logged, assigned to specific engineers, categorized, prioritized, and tracked visually until resolution.

2. Requirement Gathering

Implemented in Project

Functional Requirements

  • User Authentication: User registration, secure login with bcrypt password hashing, and JWT stateless session authorization.
  • Issue CRUD: Create new issues, view full issue details, edit existing issue attributes (status, assignee, priority), and delete issues.
  • Developer Assignment: Assign tasks to specific registered developers from team user roster.
  • Filtering & Live Search: Instant debounced keyword search on issue titles/descriptions; filtering by Status (Open, In Progress, Resolved), Priority (High, Medium, Low), Category (Bug, Feature, Task, Improvement), and Sorting (Newest, Oldest, Priority, Title).
  • Dashboard Visual Analytics: Real-time stat metrics cards and interactive Status Donut Chart & Priority Bar Chart via Chart.js.

Non-Functional Requirements

  • Performance: Under 200ms API response time using native Node.js asynchronous I/O and Vanilla JS client rendering without framework overhead.
  • Security: 10-round salted bcrypt password hashing, JWT header verification, parameterized SQL query injection prevention.
  • Availability & Cloud Accessibility: 24/7 public accessibility hosted on Render Linux containers (`devtrack-system.onrender.com`).

SQL JOIN Query Example (`issueModel.js`)

SELECT 
  i.id, i.title, i.description, i.status, i.priority, i.category,
  i.reporter_id, i.assignee_id, i.created_at, i.updated_at,
  r.name as reporter_name, r.email as reporter_email,
  a.name as assignee_name, a.email as assignee_email, a.avatar_url as assignee_avatar
FROM issues i
LEFT JOIN users r ON i.reporter_id = r.id
LEFT JOIN users a ON i.assignee_id = a.id
WHERE 1=1 AND i.status = ?
ORDER BY i.created_at DESC;

7. Backend Development (Node/Express)

Implemented in Project

  • `server.js`: Entry point. Configures CORS, JSON body parser, static serving of `/frontend`, mounts routes under `/api`, handles 404/500 errors, and listens on `0.0.0.0:PORT`.
  • `config/db.js`: Connection pool manager using `mysql2/promise`. Auto-creates database schema and sample data on startup. Includes clean fallback data engine if MySQL service is offline.
  • `middleware/authMiddleware.js`: Intercepts protected requests, extracts JWT from `Authorization: Bearer ` header, verifies validity using `JWT_SECRET`, and attaches `req.user`.
  • `models/issueModel.js`: Formulates parameterized SQL queries (`?`) with `LEFT JOIN` on `users` table twice to fetch reporter and assignee metadata safely.

8. Frontend Development (Vanilla JS SPA)

Implemented in Project

  • `config.js`: Dynamically computes `API_BASE_URL` as `${window.location.origin}/api`, ensuring seamless operation locally or on cloud servers.
  • `api.js`: Handles HTTP GET, POST, PUT, DELETE requests. Automatically attaches `Authorization: Bearer ` and handles 401 unauthorized session expiration.
  • `auth.js`: Handles login/register tab switching, token persistence in `localStorage`, and profile rendering.
  • `issues.js`: Manages table rendering, modal data population, live debounced search, multi-filters, and delete confirmations.
  • `charts.js`: Manages Chart.js doughnut and bar chart instances.

9. Authentication & Security

Implemented in Project

  1. Registration: User submits credentials. Backend generates a 10-round salted bcrypt hash using bcrypt.hash(password, 10) and stores it in MySQL.
  2. Login Authentication: Backend retrieves user by email and compares entered password using bcrypt.compare().
  3. Token Generation: Upon verification, backend signs a JWT payload containing { id, email, name, role } using JWT_SECRET valid for 7 days.
  4. Protected Requests: Client stores token in localStorage and attaches it to request headers as Authorization: Bearer <token>.
  5. Verification Middleware: authMiddleware.js verifies token validity before passing control to API controllers.

11. CRUD Process Walkthrough

Implemented in Project

  • Create (POST /api/issues): Inserts new task record into `issues` table with title, description, category, status, priority, reporter ID, and assignee ID.
  • Read (GET /api/issues & GET /api/issues/:id): Executes SQL query with `LEFT JOIN` on `users` table to fetch issue details alongside reporter and assignee names/avatars. Supports live keyword search, status filtering, and priority sorting.
  • Update (PUT /api/issues/:id): Updates existing issue fields in database.
  • Delete (DELETE /api/issues/:id): Executes SQL `DELETE FROM issues WHERE id = ?` to remove task records.

27. 40 Mayvel Technologies Interview Q&A

Q1: Why did you build DevTrack System?
To solve problem visibility in software teams by centralizing bug tracking, developer assignments, status updates, and workload metrics into a secure web dashboard.
Q2: What is your technology stack?
Node.js, Express.js, MySQL (`mysql2/promise`), Vanilla JavaScript, HTML5, CSS3, Chart.js, bcrypt, JWT, and Render.
Q3: How does authentication work?
Passwords are hashed with 10-round bcrypt. Login returns a signed JWT token valid for 7 days. Client attaches token as `Authorization: Bearer ` for protected route access.
Q4: How do you prevent SQL Injection?
All queries use parameterized statement placeholders (`?`) with `mysql2/promise`, ensuring inputs are safely sanitized.
Q5: How do SQL JOIN queries improve performance?
Using `LEFT JOIN` on `users` twice fetches issue metadata, reporter name, and assignee name/avatar in a single database query, avoiding N+1 query overhead.
Q6: Why did you choose Vanilla JS over React?
Vanilla JS demonstrates strong fundamental core skills in DOM manipulation, Async/Await, and Fetch API without framework dependency.
Q7: What is the purpose of connection pooling?
Reuses active MySQL connection instances rather than opening and closing new connections on every HTTP request.
Q8: How is the app deployed on Render?
Deployed as a Linux Node.js container listening on `0.0.0.0:PORT`, running `npm start` (`node backend/server.js`).
Q9: How do stat counters stay in sync?
Frontend calls `GET /api/dashboard/stats`, backend calculates aggregate counts from MySQL, and UI DOM elements update dynamically.
Q10: What HTTP status codes do you use?
200 OK for successful requests, 201 Created for new resources, 400 Bad Request for validation errors, 401 Unauthorized for auth failures, 404 Not Found, 409 Conflict for duplicate emails, and 500 Internal Error.
